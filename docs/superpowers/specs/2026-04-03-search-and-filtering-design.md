# Design Spec: Search & Filtering

**Date:** 2026-04-03
**Status:** Approved
**Topic:** Global content search and hashtag-based organization.

---

## 1. Goals
- Implement a dedicated "Find in All Notes" overlay (Cmd+Shift+F).
- Support inline hashtags (`#tag`) for organization without explicit metadata management.
- Provide a responsive, keyboard-driven search experience with content snippets.
- Keep the existing Command Palette (Cmd+K) focused on application actions and navigation.

---

## 2. User Experience

### A. Global Search Overlay (Cmd+Shift+F)
- A modal overlay that appears centered on the screen.
- As the user types, it performs a full-text search across all notes.
- Results are displayed as a list of "Note Groups".
- Each group shows the Note title and 1-3 snippets of text where the match was found.
- Snippets highlight the search term and show surrounding context (+/- 40 characters).
- Up/Down arrow keys navigate through matches across notes.
- Enter opens the selected note and (ideally) scrolls to the match location.

### B. Inline Tags (#tag)
- Any word prefixed with `#` in the Markdown editor is treated as a tag.
- Tags are automatically indexed by the system.
- Typing `#` in the Global Search Overlay triggers a "Tag Suggestions" mode, listing all unique tags.
- Selecting a tag filters the search results to only notes containing that tag.

---

## 3. Architecture

### A. SearchEngine (New Component)
- **Responsibility:** Executing queries against the SwiftData store and generating displayable results.
- **Input:** Search query string, list of all notes.
- **Output:** `[SearchResult]` where each result contains a note reference and a list of contextual snippets.
- **Logic:** Uses case-insensitive matching. Snippets are generated by finding occurrences in `note.content` and extracting substrings.

### B. TagManager (New Component)
- **Responsibility:** Parsing and indexing unique tags from all notes.
- **Mechanism:** Scans all notes for the regex `/(^|\s)#([a-zA-Z0-9_\-\/]+)/`.
- **Optimization:** Results should be cached or derived efficiently to avoid blocking the UI.

### C. GlobalSearchOverlayView (New Component)
- **UI:** Similar style to `CommandPaletteView` but optimized for richer content.
- **State:** `query: String`, `results: [SearchResult]`, `selectedIndex: Int`.
- **Keyboard Handling:** Standard list navigation plus a global shortcut listener in `ContentView`.

---

## 4. Implementation Plan (High Level)
1. Register global shortcut `Cmd+Shift+F`.
2. Create `SearchEngine` and `TagManager` logic.
3. Build `GlobalSearchOverlayView` with snippet rendering.
4. Integrate with `ContentView` overlay stack.
5. Add "Open Note at Line" functionality to the editor.

---

## 5. Constraints & Edge Cases
- **Large Notes:** Search should be debounced (e.g., 200ms) to maintain performance.
- **Overlapping Matches:** Ensure snippets don't overlap if multiple matches are close together.
- **Markdown Markers:** Search should ignore/strip basic Markdown markers when calculating snippet context for better readability.
